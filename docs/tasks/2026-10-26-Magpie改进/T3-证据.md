## 行为设计

1. **写入时机**：仅测试出结论时写（成功分支 / catch 分支）。点测试瞬间不清旧结论——按规格「直到用户再次测试才更新」，旧结论保留到新结论到达；测试进行中有按钮 spinner 表达忙碌。
2. **两态 + 具体原因**：成功 `.is-success` + check 图标，文案 `连接测试通过：${msg}`；失败 `.is-error` + x 图标，文案 `连接测试失败：${message}`（message = invoke 抛出的具体原因，如密钥无效/连接拒绝）。**文案逐字复用现有 toast 结论原文，未新造文案**。
3. **注入防护**：结论文本用 `textContent` 写入（上游错误串可含任意字符）；图标 innerHTML 为模块内常量 SVG。
4. **保留语义**：结论持续保留，仅两个更新路径——下次测试覆盖（replaceChildren 式重写）、离开页面清除。
5. **清除收口（场景③）**：全部切页都经 `navigateTo`（关编辑器/取消/保存回列表、切主 tab、同 tab 进 eval）。收口判据「目标页 ≠ provider-editor 即清」：
   - `settings` 在 navigateTo 里是弹窗早退，不到收口处——设置浮层不算离开页面，结论保留（正确语义）；
   - 回到编辑器必先经过一次离开（列表页点「编辑」），旧结论已在离开时清掉，天然满足「回来不显示旧结论」。
6. **竞态判据**：测试在途时切页，迟到的 `invoke` 结论若照写会残留到下次进入编辑器。已在成功/失败分支加会话判据 `editorPageActive()`（`#page-provider-editor` 是否 active），页面已离开则丢弃结论不写回（toast/弹窗行为保持原样不动）。

## 三场景 ↔ 实现机制

| 验收场景 | 机制 |
|---|---|
| ①填错密钥点「测试连接」→ 结果区出现失败原因且不被自动清掉 | catch 分支写入 `.is-error` + `连接测试失败：${message}`；无任何定时清除逻辑 |
| ②再次测试 → 内容被替换 | 每次结论写入整体重写节点内容与两态类名 |
| ③切换页面再回来 → 不显示旧结论 | navigateTo 离开即清 + 迟到结论 `editorPageActive()` 判据丢弃，双路径都断 |
